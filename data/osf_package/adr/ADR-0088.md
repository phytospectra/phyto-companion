### ADR-0088: OSF project registered as the citable acceptance-evidence archive (embargoed until owner flip); registration is created, never edited post-hoc

- **Status:** accepted (implementation pending owner-provided OSF token)
- **Date:** 2026-10-31
- **Context:** The M0–M1 acceptance evidence (ADR-0085..0087: pinned MZmine
  batch, validated live runs, vendor-conversion chain) lives in
  `data/validated_runs/` and `docs/`, but a git repo is a moving target and
  neither MassIVE nor Zenodo (third-party data sources) provides a stable
  citable artifact for THIS platform's own verification runs. The platform
  needs a DOI-citable, timestamped snapshot of the acceptance evidence that
  reviewers can check independently of the repo's future history.
- **Decision:** Register an OSF **project** (not a preprint, not a
  registration of the whole repo) containing only the acceptance-evidence
  subset:
  - `data/validated_runs/M1a/` + `M1b/` — run summaries, batch XMLs,
    feature CSVs, redacted engine logs (identity/paths redacted before
    upload; personal data rules per DATA_GOVERNANCE §PII);
  - the ADR-0085..0088 text (copied, not the whole DECISIONS.md);
  - `CITATION.cff` snapshot and the exact commit SHA it documents.
  Third-party data (mzML/.raw from MSV000090047) is NOT re-uploaded: it is
  referenced by accession + checksum, staying within CC-BY-4.0 attribution
  duties without redistributing bulk instrument files. Everything uploaded
  is the platform's own output — Apache-2.0/CC0-applicable platform work
  product.
- **Embargo:** the registration is created **embargoed** (OSF supports
  viewable-but-not-public embargo until an end date the owner sets). The
  owner flips it public (or abandons the registration) — that act is the
  owner's, not the agent's, because a public registration is immutable.
- **Alternatives considered:** Zenodo GitHub integration (repo-level DOI)
  — rejected for now: the repo contains owner-specific data that must stay
  private until the owner decides the release boundary; OSF lets us carve
  exactly the evidence subset. figshare — same reasoning, less lifecycle
  control.
- **Consequences:** `scripts/osf_register_evidence.sh` creates the project,
  uploads the subset, and records the OSF GUID back into
  `data/validated_runs/osf_registration.json`; it fails closed without
  `OSF_TOKEN`. Nothing in CI depends on OSF. After the owner makes it
  public, the DOI lands in `CITATION.cff` (`identifier`/`url`) at the next
  release.
