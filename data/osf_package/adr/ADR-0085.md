### ADR-0085: MZmine 4.11 batch contract pinned and validated to the CLI login gate; feature run pending a user profile

- **Date:** 2026-10-31
- **Status:** accepted (implementation contract recorded; the live
  feature-processing run itself is still pending one user action,
  superseding ADR-0084's blanket "unverified" framing)
- **Deciders:** Project owner (multi-vendor brief, M0-b + M1-a)
- **Context:** The brief requires one experimental LC–MS/MS mzML
  dataset with documented reuse rights, accession, checksum, and
  independently checkable expected signals (M0-b), and a valid batch
  method for a pinned MZmine version run through the platform's normal
  entry point (M1-a). ADR-0084 had refused to commit an untested XML
  format; this record replaces it with a measured contract and its
  exact boundaries.
- **Facts established (measured, not assumed):**
  1. **Dataset (M0-b):** MassIVE `MSV000090047`, file
     `20220426_UMETAB266_POS_Tetracycline.mzML` (Thermo Orbitrap ID-X,
     positive mode; 4,988 scans = 782 MS1 + 4,206 MS2; RT 0.708–11.002
     min), 33,379,150 bytes, MD5
     `396f11793f20870de150b56408a33c21` (matches the Zenodo record
     10.5281/zenodo.6948449), local SHA-256
     `fa3910452ae96f754a3eb05b2cf07ae2993f053fa4862b78d365cf1d857f6b9e`.
     Rights: MassIVE states CC0 1.0 while the Zenodo mirror records
     CC-BY-4.0; the divergence is recorded in `docs/DATA_SOURCES.md`
     §11 and CC-BY-4.0 attribution is treated as the stricter
     redistribution term. Independent anchors: the mzML's own scan
     metadata, MassBank `MSBNK-BAFG-CSL23111012700` (tetracycline
     [M+H]+ at m/z 445.1605, dl-de/by-2-0), and formula arithmetic on
     the file's own MS2 fragments.
  2. **Batch contract (M1-a):**
     `services/metabolomics/app/batch_xml.py` generates the
     version-pinned XML batch — 11 steps: AllSpectralDataImport →
     MassDetection (MS1) → MassDetection (MS2) → ModularADAP
     chromatogram builder → Savitzky-Golay smoothing → local-minimum
     resolver → isotope grouper → join aligner → multithreaded gap
     filling → duplicate filter → modular CSV export. Element names,
     parameter names, enum values and `parameter_version`s were
     extracted from the official v4.11 integration-test batch
     (`workshop_dataset_full.mzbatch`, executed headlessly by MZmine's
     own CI) and cross-checked against `BatchQueue.java`. Module class
     names and parameter versions were verified identical at tags
     v4.10.90 and v4.10.6; the generator refuses any other version and
     each export embeds the engine version and batch SHA-256 in
     provenance.
  3. **CSV export schema:** `parse_mzmine_csv` expects the
     CSVExportModular header (`id, mz, ..., rt (minutes), ...` plus
     `datafile:<name>:<quantity>` per-file columns) and maps it to the
     platform FeatureTable (RT minutes → seconds), failing closed on
     missing columns or an empty export.
  4. **CLI login gate (the blocker):** MZmine batch mode requires an
     authenticated user. Measured on this machine: 4.11.0, 4.10.90 and
     4.10.6 all abort batch execution ("Requires user login" / "Invalid
     user: You need to be logged in to continue"); the gate exists in
     source since v4.0.x. Authenticated options measured from the CLI:
     `-cli-token` (token from the mzio account console; recommended for
     automatic pipelines), `-login` (interactive browser sign-in,
     writes an `.mzuser4` profile), `-user <file|name>` (the offline
     `.mzuser4` file, machine-locked). No account was created and no
     credentials were supplied; none may be on the user's behalf
     without authorization.
  5. **Partial-run evidence:** a generated batch was accepted by
     MZmine 4.10.90, which parsed all 4,988 scans of the dataset
     before stopping at the login gate. This validates mzML import
     parsing and batch-XML acceptance only — mass detection, feature
     resolution, alignment and CSV export were never executed and
     must not be claimed.
- **Decision:**
  1. The supported engine set is exactly (4.11.0, 4.10.90, 4.10.6);
     the login gate is unconditional across all of them and
     `MZMINE_USER_FILE` is required in real mode, fail-closed at
     detect time (and `MZMINE_HOME` fail-closed at startup per
     ADR-0078).
  2. The CLI invocation is `mzmine -user <profile> -batch <xml>`
     without `-input`/`-output` overrides: the resolved input paths
     are written into the import step and the exact CSV output path
     into the export step. MZmine documents `-output` as renaming
     every export file with module-specific suffixes, which would
     make the parser's expected path a guess instead of a contract;
     `-input`'s documented forms (glob or one-path-per-line text
     file) are both less exact than the batch-embedded list.
  3. `DetectParams.noise_threshold` maps to the ADAP absolute noise
     and to bounded "factor of lowest signal" values for the two mass
     detection steps, so a requested sensitivity is honoured rather
     than silently ignored.
  4. Vendor-native conversion (.raw/.d) stays out of this contract —
     separate acceptance test (M1-b).
- **Alternatives considered:** MZmine 3.x (pre-login-gate CLI) as an
  unauthenticated fallback — rejected: it is a different engine
  generation with a different batch format, and pinning a legacy
  engine to dodge an authentication requirement misrepresents the
  current tool; `mzmine -login` run by the agent — rejected: it
  requires the user's mzio credentials and accepting terms on their
  behalf, which is not authorized.
- **Consequences:** M1-a is implemented and unit-tested end to end but
  has NOT produced a feature table yet: the first real run needs
  `MZMINE_USER_FILE` pointing at a user-created `.mzuser4` profile.
  Once available, the recorded replay is
  `scripts/replay_mzmine_m0b.sh` (pytest entry constructing the
  validated config, plus an HTTP example). Status documents must keep
  distinguishing: batch contract validated (measured), mzML import
  validated (measured, 4,988 scans), feature processing/export
  expected-but-unobserved, scientific validation not started.
